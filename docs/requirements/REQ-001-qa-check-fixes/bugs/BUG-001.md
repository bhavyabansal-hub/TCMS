## Environment
Branch `improvements`, commit `520c9f1`. DB `127.0.0.1:5500/tcms_test` (read-only SELECT through `scripts/cleanup-req001-testdata.mjs` dry run). Account involved: `qa1@tcms.com` (data only, no login used).

## Steps to reproduce
1. Seed the database (`src/app/api/seed/seed.service.ts`). This writes the qa1 report with `reportDate: today` where `today = new Date()`, a full timestamp with a time of day.
2. On the same calendar day, as qa1, save a report on `/tasks` (`POST /api/task-reports` with `reportDate: "YYYY-MM-DD"`). The service runs `new Date(input.reportDate)`, which gives midnight UTC.
3. `SELECT task_report_id, report_date FROM task_reports tr JOIN users u ON u.user_id = tr.reported_by_id WHERE u.email = 'qa1@tcms.com' AND DATE(report_date) = '<that day>'`

## Expected
One report per user per calendar day: the upsert (`findTaskReportByUserAndDate`) finds the seed row and updates it, and the unique key `(reported_by_id, report_date)` blocks a second row.

## Actual
Two rows for qa1 on 2026-10-15. The exact-match lookup (`task-reports.repository.ts:72`, `report_date = ?`) misses the seed row, and the DATETIME(3) unique index (`migration.sql:231`) treats `14:09:58.210` and `00:00:00.000` as different keys.

## Evidence
```
evidence/r9-dryrun-2.txt (2026-10-15, SELECT only):
  task_reports fc2f0e2f-e360-4eaa-806d-82ed11c0f204 | qa1@tcms.com | report_date 00:00 (QA-check report, "QACHECK task")

src/app/api/seed/seed.service.ts:283  const today = new Date()
src/app/api/seed/seed.service.ts:294  reportDate: today,
src/app/api/task-reports/task-reports.service.ts:194  const reportDate = new Date(input.reportDate)
```
Effect in the UI (not checked here, tester to confirm): the day can show two reports for qa1, or the `/tasks` page loads only one of them. The weekly-hours stats then count both.

## Root cause (developer)
Probably the seed: it writes `new Date()` and `today - 24h` with no truncation to midnight UTC, while every app write path stores a date-only value. To be confirmed by developer-backend.

## Fix (developer)

## Regression test (sdet)
Proposed: after a seed, `SELECT COUNT(*) FROM task_reports WHERE TIME(report_date) <> '00:00:00'` = 0, plus a POST for the seed day that updates the seed row (200, same `task_report_id`).

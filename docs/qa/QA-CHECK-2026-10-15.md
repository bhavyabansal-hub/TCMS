### Bugs
1. **S3: viewer sees the work-log editor on /tasks.**
   - **Repro:** log in as viewer → /tasks → type a description and 15 min → Save report.
   - **Result:** request returns 403, toast says "Insufficient role".
   - **Cause:** `src/components/views/tasks.tsx:182` sets `isReadOnly` only when viewing someone else's log; it never checks `create_task_report`. This breaks the rule "not granted → hidden".
2. **S4: dashboard buttons aren't permission-gated.**
   - "New Test Case" and "Report Bug" in the header (`dashboard-v2.tsx:279-291`) are shown to every role.
   - The Quick Actions "New Test Case", "Report Bug", "Reviews" and "Reports" (`dashboard-v2.tsx:682-687`) are too.
   - **Repro:** log in as viewer → /dashboard → click "Reviews" → "Access restricted"; click "New Test Case" → a list with no create button.
3. **S4: needless 403 calls from pages.**
   - `test-case-detail.tsx:69-73` fetches the activity log without checking `view_activity_logs`, giving a 403 on every test-case page for dev, QA and viewer.
   - `integrations.tsx:68-75` fires three queries, and `activity-log.tsx:88-92` fires one, before the permission check, giving 403s for roles without access.
   - The UI handles this gracefully, but it adds noise to the WARN log.
4. **S4: documentation drift.**
   - The battery count is 63 in agent.md §3 but 67 in CODEBASE-MAP §10.
   - `auth-screen.tsx` is listed under views but lives in `src/components/`.
   - `.zscripts/` is called load-bearing but doesn't exist here.
5. **S3 (test tooling): verify-review-matrix.mjs is out of date.**
   - Lines 52 and 72 expect `perform_review OR submit_review` to grant the reviews list and `module-reviews?action=all`.
   - The services now require `perform_review` only (`reviews.service.ts:59`, `module-reviews.service.ts:105`), which matches CODEBASE-MAP §4.
   - **Repro:** `node scripts/verify-review-matrix.mjs` → 2 failures for qa_engineer.
6. **S3 (test tooling): verify-wiki.mjs isn't ported to MySQL.**
   - Lines 231-233 use the PostgreSQL syntax `INSERT … ON CONFLICT (role, action)` through Prisma raw SQL, which is invalid on MySQL.
   - It would throw before the cleanup at lines 251-271, leaving 6 `wiki-*-<stamp>@tcms.test` accounts (including a VP with a hard-coded password) and their docs in the database.
   - Found by reading the code; I didn't run it.
7. **S3 (test tooling): verify-permission-matrix.mjs needs data this database doesn't have.**
   - It needs `qamarathon.*@tcms.dev` users and a "QA Marathon Alpha" module; this database has only the 7 demo users.
   - Line 284 deliberately re-enables developer `perform_review`. On a default-matrix database, that leaves a permanent non-default override.
   - I didn't run it.

**Observation (not a bug):** `.env` has `TCMS_ALLOW_SIGNUP=true`, so self-registration is open on this machine. The docs say it must be false in production.
